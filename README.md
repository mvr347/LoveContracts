# LoveContracts

Ежедневная система контрактов (в духе Witcher 3): доска заданий, ротация раз в сутки, награды и штрафы.
Плюс отдельная система player-to-player контрактов (`/pcontract`) — игроки нанимают друг друга,
а не только берут задания у системы.

## 1. Ежедневная доска контрактов (`/contracts`)

Раз в сутки (по умолчанию в 00:00) плагин выбирает пул активных контрактов из `contracts.yml` (взвешенный случайный выбор по редкости: easy/medium/hard), и игроки принимают их через `/contracts`, доску на NPC (LoveEssential) или обычную табличку. У каждого контракта есть условие выполнения (убить мобов, добыть руду, поймать рыбу, скрафтить предмет), награда и штраф за провал/истечение срока.

Награда и штраф — исключительно физическая валюта через `LoveCore.LoveEconomy` (тот же кошелёк, что и во всей экосистеме); предметы, опыт и репутация наградой/штрафом не выдаются. Без LoveCore денежные награды/штрафы просто пропускаются.

### Команды

| Команда | Алиасы | Описание | Пермишин |
|---|---|---|---|
| `/contracts` | `contract`, `контракты` | Открыть доску контрактов | `lovecontracts.use` |
| `/contracts stats` | — | Открыть статистику игрока | `lovecontracts.use` |
| `/contracts abandon <id>` | — | Отказаться от контракта | `lovecontracts.use` |
| `/lovecontractsadmin` | `lovecontracts`, `lc`, `lca`, `lcadmin` | Администраторские команды | `lovecontracts.admin` |

### Подкоманды `/lovecontractsadmin`

- `reload` — перезагрузить config.yml, contracts.yml и цепочки (npc_quests.yml, npc_stories.yml, chains.yml)
- `chains` — игровой конструктор цепочек поручений (см. раздел «Конструктор цепочек»)
- `rotate` — принудительно запустить ротацию контрактов
- `npc` — привязать NPC LoveEssential, на которого смотрит игрок (правый клик открывает доску)
- `sign` — подсказка по созданию таблички-контракта (без привязки — любая табличка с нужными строками работает)
- `complete <player> <contractId>` — принудительно засчитать выполнение
- `fail <player> <contractId>` — принудительно засчитать провал
- `stats <player>` — открыть статистику другого игрока
- `reset <player>` — сбросить дневные счётчики игрока
- **Цепочки поручений игрока** (не трогают ежедневные контракты; игрок в сети или уже заходивший на сервер):
  - `chain start <игрок> <цепочка>` — запустить с первого этапа, без NPC, кулдауна, одноразового правила и лимита в три цепочки
  - `chain clear <игрок> <цепочка|all>` — стереть запись целиком (прогресс, история, кулдаун, счётчик): цепочку можно пройти заново
  - `chain complete <игрок> <цепочка> [--no-reward]` — завершить сразу; награда выдаётся, если игрок в сети (лимит заработка не применяется)
  - `chain fail <игрок> <цепочка>` — провалить как отказ: без награды и кулдауна, цепочку можно взять снова
  - `chain step <игрок> <цепочка> <номер>` — перевести активную цепочку на этап (с 1)
  - `chain info <игрок>` — цепочки игрока: статус, этап, прогресс, число прохождений, время завершения
- `diag` — диагностика (загруженные контракты, активные сейчас, статус LoveCore/PlaceholderAPI/LoveEssential)

### Контракты (`contracts.yml`)

Каждый контракт — запись с условием, наградами и штрафами:

```yaml
contracts:
  kill_zombies_easy:
    display-name: "<green>Kill 50 Zombies</green>"
    description: "Slay 50 zombies anywhere on the server"
    difficulty: "EASY"          # EASY | MEDIUM | HARD
    type: "REPEATING"           # REPEATING | ONE_TIME
    enabled: true
    weight: 10                  # вес при взвешенном случайном выборе в ротации
    daily-spawns: 1             # сколько "слотов" этого контракта создаётся за ротацию
    max-acceptances: -1         # максимум принятий за ротацию; -1 = без ограничения
    expiration-hours: 24
    condition:
      type: "KillEntity"        # KillEntity | MineMaterial | CatchFish | CraftItem
      entity-type: "ZOMBIE"
      count: 50
    rewards:
      money: 500                # монеты через LoveCore.LoveEconomy
      items:
        - "DIAMOND 1"
        - "OAK_LOG 16"
    penalties:
      none: true                # или money: -100 / отсутствие блока = нет штрафа
```

Условия (`condition.type`):
- `KillEntity` — убить `entity-type` (Bukkit `EntityType`) × `count`
- `MineMaterial` — добыть блок `material` (учитывает deepslate-варианты руд) × `count`
- `CatchFish` — поймать рыбу × `count`
- `CraftItem` — скрафтить предмет `material` × `count`

### Конфигурация (`config.yml`)

#### Ротация

```yaml
rotation:
  enabled: true
  time: "00:00"              # время ежедневной ротации (серверное)
  daily-count: 20             # сколько контрактов активно одновременно

  difficulty-distribution:
    easy: 60                  # % от daily-count
    medium: 30
    hard: 10

  notify-rotation: true
  rotation-announcement: "<green>✓ New contracts are available! Use /contracts</green>"

  warning-before-expiration-minutes: 5
  expiration-warning: "<yellow>⚠ Your contracts expire in {TIME} minutes!</yellow>"
```

#### Награды и штрафы

```yaml
rewards:
  enabled: true
  # Денежные награды платятся через LoveCore.LoveEconomy (физические монеты в инвентаре) —
  # общая валюта экосистемы. Молча пропускаются, если LoveCore не установлен.
  money:
    enabled: true
  items:
    enabled: true
  reputation:
    enabled: false
    integration: "lovebehavior"   # точка интеграции, ещё не подключена

penalties:
  enabled: true
  # Денежные штрафы списываются через LoveCore.LoveEconomy, но не больше текущего баланса
  # игрока — у физической валюты нет долга.
  money:
    enabled: true
  reputation:
    enabled: false
  track-failures: true
```

#### GUI

```yaml
gui:
  enabled: true
  title: "<gradient:#55FF55:#55FFFF>Contract Board</gradient>"
  auto-update: true
  update-interval-ms: 500

  difficulty-colors:
    easy: "green"
    medium: "yellow"
    hard: "red"
```

#### Единая доска (с 2026-11-21)

`/contracts`, `/pcontract`, NPC доски, таблички и NPC с несколькими поручениями открывают **одну** доску на 54 слота
(стандарт gui_gen, RULE 8). В шапке в слотах 2-7 четыре вкладки, фильтр и сортировка вкладки:

| Вкладка | Что показывает | Действия |
|---|---|---|
| **Обычные** | ежедневные контракты сервера | ЛКМ принять (с подтверждением), ЛКМ по взятому сдать, ПКМ отказаться (с подтверждением) |
| **Цепочки** | многошаговые поручения NPC | ЛКМ взять (с подтверждением), ПКМ поговорить с заказчиком, у взятой ЛКМ продолжить, Shift+ПКМ отказаться (с подтверждением) |
| **От игроков** | открытые заказы других игроков (`/pcontract`) | ЛКМ принять; кнопка внизу подсказывает команды создания заказа |
| **Мои** | контракты с игроками, которые вы заказали или исполняете | ЛКМ отменить или отказаться (с подтверждением) |

До 21 карточки на странице, стрелки на слотах 36 и 44 появляются только при нескольких страницах. Снизу: слот 51 — кнопка
вкладки (текущий контракт, подсказка по созданию заказа), слот 53 — «Закрыть».

Окно подтверждения — серверное 27-слотовое с фоном ItemsAdder, без ItemsAdder и PlaceholderAPI — 9-слотовое окно по
стандарту. Диалог NPC тоже оформлен по стандарту: ответы центрируются в одном ряду. Цепочку можно взять прямо с доски: первый
этап любой цепочки — разговор с заказчиком, поэтому история не пропускается. От цепочки можно отказаться: без награды и без
перерыва, её можно взять заново. Одновременно можно вести до трёх цепочек.

#### NPC (LoveEssential)

```yaml
npc:
  enabled: true
  info-update-interval: 10
  # Привязывается через /lovecontractsadmin npc (посмотреть на NPC перед командой).
  # Ключ NPC LoveEssential строкой: ext-xxxxxxxx, имя или номер NPC ("5"). Других провайдеров NPC нет.
  # Пусто = NPC не привязан, доска всё равно доступна через /contracts и таблички.
  # Старый числовой npc.id при запуске переносится в npc.key автоматически.
  key: ""
```

#### Таблички

```yaml
signs:
  enabled: true
```

Любая табличка с первой строкой `[LoveContracts]` и второй строкой = id контракта из `contracts.yml` работает на приём контракта по правому клику — привязка не требуется, проверка идёт по содержимому таблички в момент клика.

#### База данных

```yaml
database:
  file: "contracts.db"   # только SQLite
  pool-size: 10
  connection-timeout: 30000
  leak-detection-threshold: 15000
```

Таблицы: `active_contracts` (текущая ротация, счётчик принятий на слот), `player_contracts` (кто что принял/выполнил/провалил, с уникальностью на игрока+контракт+день), `contract_stats` (дневные/суммарные счётчики, серии побед).

### Конструктор цепочек (`/lovecontractsadmin chains`)

Игровое меню для админа: цепочки поручений без правки yml-файлов. Список всех цепочек сервера: свои (из `chains.yml`) можно
править и удалять, цепочки из `npc_quests.yml` и `npc_stories.yml` показаны только для справки.

- **Редактор цепочки** (54 слота): заказчик (выбор из NPC LoveEssential, NPC в прицеле или ключ вручную, в том числе
  `@actor:имя`), название, награда (медные единицы, предел `economy.contracts-v2.max-reward`), повтор и перерыв, сохранение,
  удаление. Этапы — карточки по порядку: ЛКМ изменить, ПКМ поднять выше, Shift+ПКМ удалить. Последняя карточка добавляет этап.
- **Редактор этапа** (36 слотов): тип (убить, добыть, скрафтить, поймать рыбу, передать предметы, поговорить с NPC, прийти на
  место) и только те параметры, которые нужны типу: предмет (из руки или названием), существо, NPC, количество, место
  (ваша позиция и радиус; у этапа «прийти на место» обязательно, у остальных ограничивает, где этап засчитывается), описание.
- Диалоги создаются сами (предложение у заказчика, короткий разговор на этапах с NPC). Реплики, написанные в `chains.yml` вручную,
  конструктор при сохранении не трогает.
- Сохранение проверяет цепочку так же, как загрузчик, и **не даёт менять этапы цепочки, которую сейчас проходят игроки**: кнопка
  «Сохранить» с Shift+ЛКМ сохраняет копию под новым идентификатором `_v2`, `_v3`, ... Удалить цепочку, на которой есть игроки,
  тоже нельзя. После записи цепочки перечитываются сразу.
- Рукописные `npc_quests.yml` и `npc_stories.yml` (с комментариями) конструктор не переписывает; при совпадении id побеждает
  рукописная цепочка. Файл `chains.yml` пишется через временный файл, поэтому сбой не оставит его полузаписанным.

### Ограничения

- Денежные штрафы применяются только к онлайн-игрокам — списать физические монеты из инвентаря офлайн-игрока невозможно, поэтому провал контракта по истечении срока для офлайн-игрока не штрафуется деньгами (статистика провала всё равно фиксируется).
- Репутация (LoveBehavior) — точка интеграции обозначена в конфиге и модели наград/штрафов, но общий сервис ещё не подключён.

## 2. Player-to-player контракты (`/pcontract`, алиасы `pcontracts`, `playercontract`, `контракт`)

Игроки нанимают друг друга, а не только берут задания с доски: разместить заказ (принести
предметы, убить цель или произвольную задачу текстом) с наградой золотом, кто-то
другой его принимает, награда и эскроу рассчитываются автоматически при выполнении, отмене
или истечении срока.

### Возможности

- **Создание**: `/pcontract create <deliver|kill|custom> ...` со свободными флагами (`clanonly`,
  `rep:N`) вместо жёсткого набора аргументов.
- **Эскроу**: золото списывается у создателя через `LoveCore.LoveEconomy` (физические монеты
  в инвентаре, тот же кошелёк, что и у ежедневных контрактов) при создании и выдаётся
  исполнителю при выполнении — возвращается создателю при отмене/истечении срока. Награда —
  только эта физическая валюта, предметы наградой не выдаются.
- **Задачи**: `DELIVER_ITEM` (подтверждается через `/pcontract turnin`, сканирует и забирает из
  инвентаря), `KILL_ENTITY` (прогресс отслеживается живым `EntityDeathEvent`), `CUSTOM`
  (исполнитель сдаёт на проверку, создатель принимает/отклоняет).
- **Живой инвентарь** нужен для выдачи золота — если исполнитель офлайн в момент расчёта,
  выплата ждёт в очереди `pcontract_payouts` до следующего входа.
- **Мягкие интеграции**: гейт по репутации и видимость "только для клана" идут через
  `ReputationOracle`/`ProfileOracle` LoveCore — всё работает и без LoveCore, просто без этих
  проверок (контракты без золотой награды не требуют LoveCore вообще).
- **События**: `PlayerContractCreated/Accepted/Completed/EndedEvent` — другие плагины
  (LoveBehavior для репутации, LoveLeaderboards для статистики) могут реагировать
  самостоятельно, не будучи известными этому плагину.
- Все лимиты (границы эскроу, гейты репутации, сроки, налог на создание, лимиты на игрока)
  настраиваются в `config.yml` под `player-contracts:`.

### Команды

| Команда | Описание |
|---|---|
| `/pcontract board` | Единая доска на вкладке «От игроков» (принять по клику) |
| `/pcontract my` | Единая доска на вкладке «Мои» (как создатель и как исполнитель) |
| `/pcontract create deliver <материал> <кол-во> <золото> <часы> [флаги] <описание>` | Разместить контракт на доставку |
| `/pcontract create kill <существо> <кол-во> <золото> <часы> [флаги] <описание>` | Разместить контракт на убийство |
| `/pcontract create custom <золото> <часы> [флаги] <описание>` | Разместить произвольный контракт |
| `/pcontract accept <id>` | Принять открытый контракт |
| `/pcontract turnin <id>` | Сдать предметы по контракту на доставку |
| `/pcontract submit <id>` | Отправить произвольный контракт на проверку |
| `/pcontract review <id> accept\|reject` | Создатель принимает/отклоняет сдачу |
| `/pcontract cancel <id>` | Отменить (создатель) или отказаться (исполнитель) |
| `/pcontract info <id>` | Информация о контракте |

## Сборка

```bash
mvn clean package
```

Java 21, Paper 1.21.4+. Использует HikariCP + SQLite (шейдится в jar), Caffeine для кэша (зарезервировано под будущее использование).

## Зависимости

### Мягкие зависимости (плагин работает и без них)

- **LoveCore** — денежные награды/штрафы `/contracts` и эскроу `/pcontract` через `LoveEconomy`; без него эти операции с золотом молча пропускаются или недоступны (контракты без золота — работают)
- **LoveEssential** (через LoveCore) — NPC доски контрактов (`/lovecontractsadmin npc`) и NPC-цепочки
- **PlaceholderAPI** — плейсхолдеры статистики
